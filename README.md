## Rules (strict — see the PDF for full wording)

- **From scratch = NumPy array arithmetic.** `scipy.ndimage`, `scipy.signal`, `cv2`,
  `skimage` must **not** be used for any operation a problem asks us to implement.
  They may only be used to validate/compare against our own implementation, and only
  where a subtask explicitly asks for that comparison.
- `numpy.fft` is allowed everywhere (we implement the DFT matrix ourselves once in
  Problem 1; elsewhere `numpy.fft` is fine to use directly).
- Every number in the report must come from the machine that ran the code — CPU, RAM,
  and NumPy version are stated per problem.
- Where the PDF asks for a dated, pre-implementation written prediction, that file is
  written and committed **before** the corresponding experiment is run.
- Problem-specific subtasks call for self-synthesized images (not external ones) or
  self-captured photos — see each problem's README.

## Structure

```
docs/            assignment PDF
data/
  provided/      images supplied with the assignment, one subfolder per problem
  synthetic/     images we generate ourselves (sinusoids, step edges, etc.)
  own_captures/  self-captured photos required by Problems 5 and 6
src/dip_a2/      shared Python package (DFT machinery, filters, metrics, ...)
problems/        one folder per problem, each self-contained:
                   README.md         task checklist from the PDF
                   REPORT.md         the written report for that problem (results, numbers, figures)
                   explanation.tex/  a formal LaTeX/PDF write-up: problem statement, theory,
                     .pdf            inputs/outputs, methodology, results, conclusion
                   predictions/      dated pre-implementation predictions (where required)
                   problemN.py       implementation — run this to reproduce everything
                   results/          figures/tables generated by the code
```

There is no single combined report — each problem is written up independently in its
own `REPORT.md` and `explanation.pdf`, since each is graded (and vivaed) separately.

## Setup

```bash
git clone https://github.com/ujjuNotGujju/dip-assignment-2.git
cd dip-assignment-2

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pip install -e .          # installs src/dip_a2 as an editable package (import dip_a2)
```

Requires Python 3.9+. `requirements.txt` pulls in numpy, matplotlib, scipy,
scikit-image, opencv-python, and jupyter — note that scipy/scikit-image/opencv are
installed only for the few explicitly-sanctioned comparison checks (see **Rules**
above); the actual implemented algorithms never call them.

## Running a problem

Each problem is a single, self-contained script that regenerates everything in its
own `results/` folder (figures, tables, JSON) when run from the repo root with the
venv active:

```bash
source .venv/bin/activate   # if not already active

python problems/problem1_dft/problem1.py
python problems/problem2_frequency_filtering/problem2.py
python problems/problem3_homomorphic/problem3.py
python problems/problem4_edge_preserving/problem4.py
python problems/problem5_wiener/problem5.py
python problems/problem6_motion_blur/problem6.py
```

Each script prints its progress and machine info (CPU/RAM/NumPy version) to stdout as
it runs, and writes figures/tables into its own `problems/problemN_*/results/`
directory — the exact files referenced from that problem's `REPORT.md` and
`explanation.pdf`. Runtimes range from a few seconds (Problems 3, 6) to a few minutes
(Problems 2, 4, 5, which sweep several parameters/noise levels).

Problems 5 and 6 additionally look for real self-captured photos in
`data/own_captures/` (already included in this repo:
`low_light_noisy.png` for Problem 5 §5.2, `motion_blur.jpeg` for Problem 6 §6.4) and
process them automatically as part of the same run — no extra steps needed.

## Recompiling the explanation PDFs (optional)

The `explanation.pdf` files are already built and committed, so this is only needed if
you edit an `explanation.tex` and want to regenerate its PDF. Requires a LaTeX
distribution (e.g. TeX Live) with `pdflatex` and the `amsmath`, `graphicx`, `booktabs`,
`caption`, `subcaption`, `float`, `hyperref` packages:

```bash
cd problems/problem1_dft   # or any other problemN_* folder
pdflatex -interaction=nonstopmode explanation.tex
pdflatex -interaction=nonstopmode explanation.tex   # second pass resolves refs/TOC
```
